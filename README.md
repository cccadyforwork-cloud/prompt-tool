# 通用产品提示词生成工具 MVP

这是一个本地静态 MVP，用来根据产品资料和模板类型自动生成 Amazon 图组提示词。页面初始状态不展示内置演示参数，需先解析 Amazon 模板或供应商资料。

## 使用方式

### 两条豆包分析路线

- **01 · 1688 分析**：Amazon 模板确定当前 SKU；1688 详情图先由豆包识别。原“参考链接”的竞品 HTML 只用于提取图组 URL，竞品图组另外送豆包识别，按低优先级补充缺失参数、场景和卖点，并标明“竞品图组 · 豆包识别”；竞品页面文字不参与参数或卖点提取。
- **02 · 竞品分析**：使用 Amazon 模板和单独上传的竞品图组 HTML，按人工指定的 Amazon Child SKU 或唯一父体共享范围处理。豆包识图后，与 01 共用来源优先级合并：Amazon 标题明确参数及 Amazon 颜色字段优先，竞品识图补缺，联网只补场景和卖点，人工修改最高。Amazon 标题已有尺寸时完整保留，竞品尺寸仅在整个字段为空时填入。参数默认展示，取消逐字段采用按钮，核对后沿用 01 的整体确认与卖点锁定流程；两条路线独立保存。竞品图片仍保留来源标记，不能覆盖已确定的 SKU 身份。

### 2026-10-26 更新与验证

- 两条路线分别保存资料、参数、卖点及规划；父体共享直接使用 Amazon 模板的唯一父体，取消 1688 款式解析和自动 SKU 匹配。
- 竞品只使用当前商品主图组的豆包识别结果，不提取竞品页面文字；主图区域外的推荐商品、评论及其他图组不纳入分析，同图不同尺寸去重。
- 参数按来源优先级补缺，保留人工修改和 Amazon 明确尺寸，来源显示到类别；场景和卖点可以联网补充，异步结果不会跨路线或覆盖后续人工确认。
- 修复第 02 页进入第 03 页的阻塞：按事实选择展示方式的规划现在写入提示词，确认校验忽略参数高亮产生的空格，仍拦截真正缺少方案的提示词。
- 回归命令：`node test_source_priority.cjs`、`node test_competitor_workflow.cjs`、`node test_competitor_gallery.cjs`、`node test_plan_confirmation.cjs`、`node test_persistence.cjs`、`node test_image_pipeline.cjs`，以及 `python3 -m unittest test_product_analysis test_visual_plans test_keychain_config`。规划确认覆盖 01/02、三种展示方式和单条/双条卖点。

唯一运行入口：在项目目录运行 `python3 server.py`，然后打开 `http://127.0.0.1:4173/index.html`。不要通过 `file://` 地址或历史预览页打开；它们不会加载当前服务的解析规则、套装规则和生图 API。必须通过本地服务打开，豆包识图和联网代理才能工作。没有配置 API Key 时服务也能启动，“本地分析”路线可正常使用。

需要豆包时，先在终端设置火山方舟 Coding Plan 的 `ARK_API_KEY` 后再启动服务。项目默认通过 Coding Plan 专用地址 `https://ark.cn-beijing.volces.com/api/coding/v3` 调用，默认模型为 `doubao-seed-2.0-lite`，也可通过 `ARK_MODEL` 覆盖为套餐支持的 Model Name。不要使用普通地址 `https://ark.cn-beijing.volces.com/api/v3`，否则不会消耗 Coding Plan 套餐额度，而会产生普通方舟调用费用。01 路线先识别 1688 图片，再识别上传竞品 HTML 中的图组；仍无卖点时，联网路线才以英文商品关键词检索补充。检索词只用于搜索，不会覆盖 Amazon Child SKU 确定的商品名。

需要直接生图时配置 `GRSAI_API_KEY`。主界面分为三个完整页面，并通过顶部导航切换：第一页保持“资料解析 ↔ 提取参数”左右对应，第二页保持“人工参数 ↔ 当前任务提示词”左右对应，第三页保持“当前提示词 ↔ 参考图与生成结果”左右对应；普通桌面宽度不改成上下布局。资料解析页先选择“单品路线 / 套装路线 / 不同款组合套装”，再选择“本地分析 / 豆包识图 / 联网补充”；Amazon SKU 名称含 `Set`、`Kit`、`Bundle` 或套装字样时，绑定该 SKU 会自动切换到套装路线。“不同款组合套装”必须人工确认，避免把普通同款多件装误判为异款组合；该路线由完整组合参考图直接控制各款身份，提示词只规定完整组合、人物使用、多场景、参数与卖点图中各款如何呈现，不用文字重述产品几何。套装解析后在第二页确认主体、配件、数量及各自的 1688 来源。三页共享当前产品、模板和图组任务，人工参数保存后会重算整套提示词，已生成图片在输入变化后会提示重新生成。来源图先去重，超过 16 张时按原始清单全段均衡抽样，再由豆包按产品身份排除明显无关商品以及证书、检测报告、票据、纯文字表格等证据文档。供应商图只保留当前 SKU 同色及明确相近色候选，相近色须人工选择；竞品图不参加颜色筛选；候选图先按勾选顺序展示已选参考图，再展示未选竞品图，最后展示其他未选图。未勾选参考图时竞品图排在最前面。重复图片只显示一次。右侧最多展示 20 张候选图、人工最多选择 6 张，也可拖拽本地 JPG、PNG、WebP 图片并单张删除。人工选图路线不再把系统匹配结果冒充人工选择：操作证据图或卖点证据图会在左下角标明“系统默认”角色并默认排在提交最前，最多 2 张；人工可取消任何系统默认图，取消后提交时不会再次加入。其后严格按人工勾选顺序追加产品身份图及其他参考图，整次提交仍最多 6 张。普通候选图不重复显示“待人工核对”，竞品、相近色和当前 SKU 等必要来源标记显示在右下角；自动选图路线继续沿用原有的按图位筛选、排序和数量限制。两条路线均以最多两个并发任务批量生成整套图片，也可继续单张提交。生成结果返回后会立即保存到当前浏览器标签页的 IndexedDB，旧历史在打开页面时自动补存；刷新和下载优先使用本地副本，远端链接只作补存兜底，清除该站点数据会同时删除本地副本。全部生成后可一键保存 ZIP，遇到临时图片网关错误会自动重试。下载命名是项目级固定规则：压缩包只使用中文产品名（`产品名.zip`），内部图片只使用中文产品名加连续阿拉伯数字（`产品名1.png`、`产品名2.png`……），不追加日期、图组、图位、用途、历史轮次、连字符或其他标注；生成记录里的下载入口同样遵守此规则。中文产品名按“已提取的中文产品名 → 1688 中文标题或源文件名”依次确定，下载命名不使用内置类目映射；仍无法确定时统一使用 `产品套图`，不得回退为英文名称。VIP 模型额外支持 2048 和 2880 方图。API Key 在 macOS 上可保存到系统钥匙串，启动时读入当前服务进程，不写入页面或项目文件。

从店铺运营系统 S3 打开时，工具 URL 会携带 `store_project_id` 和 `store_sku`。这两个值共同限定当前工作记录；同一浏览器、同一本机的内嵌页与“单独打开”标签页共用该记录，不同子体相互隔离。工具会从运营系统只读接入当前项目最新登记的 Amazon 上品表、以及 S1 已保存且指纹未变化的 1688 HTML，预填到原有资料输入框；不会自动解析或覆盖已保存的解析结果。运营确认资料后，仍需手动点击“解析资料并提取产品信息”。没有已登记的原始文件时，对应输入框保持空白。首次刷新原内嵌页时，仅当旧标签页选中的产品 ID 与 URL 子体相同，或以 `-子体SKU` 结尾，才迁移旧会话资料和生图历史；旧记录不会被删除。直接打开不带这两个参数的独立工具仍保留原先按标签页隔离的模式。此功能不是跨电脑或多人实时同步；同时编辑两个标签页时，后保存者可能覆盖前者，建议一次只在一个标签页编辑。

### API Key 一次配置与自动读取（macOS）

首次运行 `python3 server.py` 时，在终端按提示输入火山方舟和 Grsai Key；输入不会显示，格式通过检查后自动保存到 macOS 钥匙串。后续启动优先使用有效环境变量，其次读取钥匙串；两者均没有可用 Key 时才提示输入。格式检查不代表远端服务已验证密钥有效。

也可以在项目目录运行 `python3 server.py --configure-keys`，单独配置或更新 Key 后退出。更新时直接回车保留原有保存值；已运行的服务需重启才能加载新 Key。环境变量中的 Key 不自动持久化，如需保存请使用此命令。

钥匙串项目服务名为 `prompt-tool.api-keys`，两个账户分别为 `ARK_API_KEY`、`GRSAI_API_KEY`，可在 macOS“钥匙串访问”中管理。如果系统询问访问权限，允许当前 Python 访问这些项目即可。读取或保存失败会显示提示，输入的有效 Key 仍可用于当前进程。其他操作系统继续使用环境变量或每次启动时输入，不保存到磁盘。

可以同时打开多个浏览器标签页处理不同产品。每个标签页分别保存上传的原始文件、解析参数、卖点图方案、候选参考图和生图历史；刷新当前标签页会从浏览器持久存储恢复，不会覆盖其他产品。带运营项目与 SKU 的链接按这两个值隔离；不带参数的独立工具按标签页隔离。浏览器标签标题会显示当前产品名，便于在并行任务之间切换。清除网站数据会删除本机保存记录，重要图片仍应及时下载。

SKU 身份和款式列表只来自 Amazon 模板。1688 资料只按人工选择的“指定 Amazon Child SKU”或“Amazon 父体共享”范围补充参数；不读取 1688 自身的 SKU 规格选项，不根据颜色、尺码或型号自动匹配两边的 SKU，也不从 1688 文件创建额外 SKU。所有供应商事实、卖点证据与参考图都跟随同一作用域，未在作用域内的 SKU 不得从整份 1688 文本回捞尺寸或其他参数。供应商图片匹配失败时暂不显示未经确认的 1688 图片，避免混入其他颜色；竞品图仍保留，第三页可用“重新筛选1688图片”重试。第 1 页左栏放置“商品组合路线”和“信息提取路线”，右栏放置“资料输入”和“资料提取出的产品参数”，不再显示独立的来源摘要模块；采集助手图片只保留链接粘贴区，不提供图片清单文件上传口。

功能：
- 输入 Amazon 类目模板 Excel、1688 HTML 文件、竞品链接 HTML 文件；1688 和竞品 HTML 可多选。
- 可输入 Amazon 类目模板 Excel，用于按子 SKU 提取采购款式；可用行号范围或 SKU 列表限定要提取的款式。
- 点击解析资料，从资料中提取产品名、款式选项、材质、颜色、结构、细节和卖点线索。
- 解析前可选择三条路线：本地分析、豆包识图整理、豆包联网补充。
- 选择解析出的当前产品 / 款式。
- 选择参数规格、功能展示、场景展示、参考链接或植物绑带模型。
- 图片类型由模板决定，一次性输出完整图组提示词。
- 修改左侧可替换参数，例如 Product Name、Material、Color、Structure、Selling Point。
- 商品展开尺寸、材质、工艺和卖点只有在当前商品资料存在证据时才自动填写；包装和物流尺寸不参与商品参数。
- 占位符在页面中以蓝色显示，复制时保留纯文本提示词。
- 每张图可单独复制，也可复制当前产品完整图组。
- 每张提示词卡片可直接调用 Grsai 生成图片，并在任务完成后预览或打开原图。

## 数据口径

- 所有分析路线都先读取 Amazon 模板，以其中的 Child SKU 作为唯一款式身份。
- Amazon 类目模板用于确认变体款式：`Parentage Level = Child` 的行数作为采购款式个数；`Variation Theme Name` 中的字段作为款式属性，例如 `SIZE/COLOR` 读取尺码和颜色。父 SKU 只用于归组，不作为采购款式。指定范围支持 `7-17`、`7,9,11-17` 或直接填写 SKU。
- SKU 和原始款式标签保持不可变，只用于识别与来源追溯；提示词中的 `Option` 不重复颜色，只保留尺寸、数量等非颜色变体事实，纯数字多件装统一写成 `2-Pack` 等明确数量标签。`Color` 始终作为独立参数输出；人工修正颜色后，提示词必须同时剔除 SKU 原始选项中的旧颜色，禁止出现新旧颜色冲突。该规则对当前页面、刷新恢复页面和所有新标签页全局生效。
- `Product Count` 从当前 Amazon Child SKU 标题提取，缺失时由人工补充；颜色优先使用该标题，其次使用 Amazon 颜色字段。1688 SKU 选项不补颜色、数量或其他参数。
- 不提取、展示或写入提示词 `Product Style` 参数；风格由所选图片模板和具体图位规则控制，避免把供应商或 Amazon 的泛化 Style 字段误当成产品事实。
- 1688 HTML 用于提取商品页面资料和图片链接，排除 1688 SKU 规格选项；01 路线中，材质、尺寸、净重、容量、适用范围、场景和卖点只接受详情图的豆包识别结果，结构与工艺另按下面的来源顺序处理。
- 本地分析路线只使用 1688 页面、结构化属性和本地 OCR，不调用豆包。
- 豆包识图路线优先把 1688 详情中的功能卖点图、材质图、结构细节图和参数图交给视觉模型，只整理有图片证据的材质、展开尺寸、工艺、结构和卖点；常规整理漏掉卖点时，会在联网兜底前对同批详情图追加一次只提取卖点的视觉检查。工厂介绍、仓储物流、服务政策、招商批发等供应商宣传图不进入候选参考图。
- 豆包联网路线只用英文商品关键词执行检索，补充仍缺失的卖点和使用场景；关键词不写回商品名，也不通过网络补精确尺寸、重量、数量、具体材质或当前商品独有配置。
- 竞品 HTML 仅提取当前商品主图组：优先读取主图缩略图区域，缺失时读取当前商品的初始图组数据或主图容器；不扫描推荐商品、评论、A+ 或其他款式的图片。同图不同尺寸版本合并，不固定截成五张；无法识别主图组时提示重新保存完整商品页。01 路线将图组另送豆包识别后按低优先级补缺，02 路线独立识别、按优先级默认展示，并在规划前整体确认。竞品页面文字不参与参数或卖点提取。
- `Surface Finish / Process` 只记录明确的制造工艺或表面处理，例如哑光、抛光、拉丝、喷粉、电镀、阳极氧化、上釉、印刷、压花、植绒、注塑或压铸；柔软、弹性、厚薄、针织密度、防滑、抗菌防臭、受力均匀和耐用等属性不得混入该字段。来源顺序为人工修改、1688 页面明确工艺、1688 详情图明确工艺、竞品图组豆包识别补缺；Amazon 和联网结果不作为该字段来源。
- 产品本体尺寸使用可增减的 `Product Dimensions` 列表，每行保存“部位名称: 数值 + 单位”。来源顺序为人工修改、Amazon Child SKU 标题中明确的尺寸、1688 详情图明确标注的尺寸、竞品图组豆包识别补缺。1688 页面文字、竞品页面文字和 Amazon 工作簿尺寸字段不作为来源；包装、物流、外箱、折叠收纳尺寸也不得进入。
- 尺寸图必须展示列表中的每个尺寸，并把箭头对应到正确轴向或产品部位；可折叠或可展开产品使用完全展开/打开状态。无法确认 `Dimension 1/2/3` 对应轴向时保留通用标签，不绘制误导性箭头。主图、场景图和卖点图只保持正确产品比例，不显示尺寸数字、箭头或标尺。
- 原 `Weight / Quantity` 拆分为 `Product Weight` 与 `Capacity`；数量继续只由 `Product Count / Set` 负责。净重来源依次为人工修改、1688 详情图明确净重、竞品图组豆包识别；容量来源依次为人工修改、Amazon Child SKU 标题明确容量、1688 详情图明确容量、竞品图组豆包识别。1688 页面文字及竞品页面文字不补这两项。净重排除毛重、包装重量、运输重量和外箱重量；容量必须有明确数值和单位。
- 01 路线其余来源顺序：`Material` 为 Amazon Child 标题明确材质 → 1688 详情图豆包识别 → 竞品图组豆包识别；`Structure` 为 1688 详情图豆包识别 → 1688 页面文字 → 竞品图组豆包识别；`Applicable Range` 为 Amazon Child 标题明确范围 → 1688 详情图豆包识别 → 竞品图组豆包识别；`Use Scene` 与卖点为 1688 详情图豆包识别 → 竞品图组豆包识别 → 联网补充。人工修改优先于所有自动提取结果。来源界面只显示来源类别，不附逐条证据文字。
- 产品名优先采用当前 Amazon Child SKU 标题提炼出的基础商品名；1688 只用于核对当前实物身份，不覆盖已确定的 SKU 商品名。
- 资料没有明确参数的产品不借鉴、不参照，只写能提取到的规格。
- 提示词中不展示冗长的 verified data 明细，只保留必要占位符。
- 场景展示模板按 8 张图输出：A 产品主体主场景、B 人物使用主场景、多场景、多角度、产品说明、卖点图 5、卖点图 6、卖点总览。
- 植物绑带模型按 5 张图输出，图片使用阿拉伯数字顺序命名：图一主图场景图、图二白底图、图三多场景使用图、图四卖点图、图五尺寸材质等产品信息详情图。

## 规则分层

- 第 2 页提供醒目的“整套卖点图方案”：每张卖点图可从当前 SKU 的卖点列表人工选择一条，选择随 SKU 和模板保存；调整后旧方案失效并自动重新规划。两张专用卖点图采用固定且互斥的展示路线：第一张必须是有明确使用动作和环境信息的真实场景使用图；第二张必须是只展示产品本身的中性棚拍图，可使用产品全貌或有依据的结构、材质、表面和物理细节特写，但不得出现人物、手、使用动作、食物、锅具、房间、生活背景或场景道具。即使自动规划失败或方案证据不足，这两条路线在通用回退提示词中也必须保留。无法用现有事实证明时模型只标记风险，不补造功能，是否展示仍由人工决定。进入第 2 或第 3 页时，如当前 SKU 尚无适用方案，页面会自动使用豆包规划；修改相关参数后会等待输入稳定再重新规划，同一参数版本自动请求最多一次，失败时仍可手动重试。逐项显示主体、产品状态、动作或细节、构图、事实依据及图间区别。规划不要求必须有优质供应商卖点图，但只能使用当前 SKU 的确认事实和卖点，不按产品类目或图号套用固定构图。
- 方案和人工展示决定随当前标签页的 SKU 保存。修改产品参数、卖点、证据或模板会使旧方案失效并触发自动重新规划；尚未人工决定的卖点图不会提交生图。方案完成后可一键确认全部卖点图展示，也可在单张方案中改为不展示。确认展示后写入对应英文提示词，匹配证据图与产品身份参考图一起传给生图接口；不展示的图位从后续流程跳过。自动规划不会自动生成图片。
- 第 2 页的“确认参数，卖点图方案与提示词，进入图组”会同步当前输入。模型给出的“无法证实”或提示词中的规划标记缺失仅作为风险提示，自动规划失败时也会保留人工决策入口；它们都不能推翻人工决定。全部卖点图可一键确认展示，需要排除时再单张决定不展示；已经人工确认展示的方案必须允许继续进入第 3 页，只有尚未完成人工决定才会停留在第 2 页。
- 卖点规划在一次豆包调用中完成整套方案和完整自检，保留原有的事实依据、展示路线、图间差异、动作与构图校验规则，并直接返回修订后的最终方案，不再为复核额外发起第二次请求。模型自检仍可能漏判，02 页应核对具体内容。“修订方案内容”支持修改动作、构图、依据和英文画面指令；模型提示和人工备注本身不控制去留，只有明确的人工“展示 / 不展示”决定控制该图位是否进入第 3 页。

- 全局规则只控制所有图片都必须遵守的底线：Amazon 1:1、清晰度、英文文字、真实产品、不编造参数、不复制竞品、不出现中文源文字。
- 模板规则只控制图组结构：参数规格模板、功能展示模板、场景展示模板、参考链接模板、植物绑带模型各自决定图片数量、主图/多场景/参数/卖点/总结图的构图任务。
- 场景展示模板的主场景图是全局模板规则：A 以产品本身为主展示并搭配对应场景，B 以人物使用产品状态为主并搭配对应场景；两者都必须有吸引力的真实生活方式场景和空间氛围，产品清楚但不能变成鞋/物品特写；需要通过环境、道具、自然光、前后景和留白建立场景吸引力。
- 所有主图只能使用一个连续、铺满画面的摄影场景，禁止圆形/几何小窗、白色描边、画中画、放大框、拼贴、分屏及带独立背景的第二产品画面。场景主图允许同款产品作为较小的辅助展示再次出现，但必须像真实物体一样直接放在同一场景中的人物服装、装备或环境表面上，并与主场景共享光线、透视、景深、接触阴影和色调；不得形成独立小图。
- 场景展示模板的多场景图是全局模板规则：必须输出 4 个完整真实使用场景，使用四宫格/四 panel 构图，每个 panel 都要有环境、道具、空间/户外上下文和自然使用动作；不能退化成产品特写、单品摆拍、细节图或选项图。
- 场景展示模板的产品说明图是全局模板规则：必须有清晰主标题，例如 `Product Information` / `Product Details`；只展示 2-3 个已验证信息点，文字要有专业层级、对齐、留白、细分割线/小图标和高级感，不能变成长文、密集表格或无质感的普通标注。
- 场景展示模板和功能展示模板的卖点图默认每张展示 1 个卖点；只有两个卖点在 1688 中指向同一证据画面、能够由一个统一展示场景自然表达时才合并到同一张图。连续卖点图不能重复卖点；图中文字只使用保留原意的 2-4 个英文词短标签，不添加额外口号、长句、重复 claim 或密集文案。
- 表面工艺作为所有图片的产品外观约束，但不自动成为卖点或场景文案；仅在材质微距图、产品细节图或产品信息图中确有展示价值时，才允许使用简短英文标签，主图和场景图不得显示工艺名称。
- 场景展示模板第 7 张卖点总览图的左下角白色圆形产品区必须严格遵守当前 SKU 数量：普通单品只展示 1 个完整产品；已确认的多 Pack SKU 展示与 Pack 数一致的完整独立产品，不得少放、多放、融合或为了构图额外复制。
- 植物绑带模型复用已有模板中对应图类的生图规则和限制：图一参考主场景图规则，根据产品实际要求决定是否出现人物模特；图二参考白底主图规则，只展示当前产品本体；图三参考多场景使用图规则；图四参考卖点图规则；图五复用其余模板中已有产品详情图 / 产品信息详情图的生图规则和限制，重点呈现尺寸、材质、结构、规格等已验证产品信息。
- 项目不使用内置类目映射、关键词类目识别或专用品类规则。产品身份、参数、结构、场景和卖点只来自当前 Amazon SKU、明确绑定的 1688 资料、图片证据及有来源的联网结果。
- `Category / 类目` 不作为产品字段，不读取 Amazon Browse Path，也不进入任何图片提示词。卖点图只能依据当前 SKU 身份、已确认卖点和产品证据设计展示方式，不得根据模型推断的类目补充结构、场景、道具、功能或声明。
- Use Scene 支持通过本地服务代理联网补全：资料提取后若少于 3 个场景，会结合当前产品身份和卖点，先生成跨境英文产品关键词，再依据公开网络证据填写 3-5 个去重的英文场景；也可在左侧手动触发或编辑。联网按钮只采用本次有证据的搜索结果，不混入旧场景。没有联网确认到场景时显示“没有参考场景信息”，不使用类目、通用或模型推测的兜底场景。
- 产品跑偏只通过当前 SKU 身份、已确认参数、参考图和通用真实性约束控制，不追加任何按类目命中的结构锁、场景、道具、卖点或文案。
- `Multiple optional colors` 默认不作为卖点，不进入卖点字段、卖点图或生成提示词。
- 下载时仅选择 1 张图片会直接保存为图片文件；选择多张图片或整套图组时才生成 ZIP 压缩包。
- 新产品适配必须改善通用证据提取或人工确认流程，不新增基于产品名称关键词触发的专用品类分支。
