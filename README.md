# 通用产品提示词生成工具 MVP

这是一个本地静态 MVP，用来根据产品资料和模板类型自动生成 Amazon 图组提示词。页面初始状态不展示内置演示参数，需先解析 Amazon 模板或供应商资料。

## 使用方式

唯一运行入口：在项目目录运行 `python3 server.py`，然后打开 `http://127.0.0.1:4173/index.html`。不要通过 `file://` 地址或历史预览页打开；它们不会加载当前服务的解析规则、套装规则和生图 API。必须通过本地服务打开，豆包识图和联网代理才能工作。没有配置 API Key 时服务也能启动，“本地分析”路线可正常使用。

需要豆包时，先在终端设置火山方舟 Coding Plan 的 `ARK_API_KEY` 后再启动服务。项目默认通过 Coding Plan 专用地址 `https://ark.cn-beijing.volces.com/api/coding/v3` 调用，默认模型为 `doubao-seed-2.0-lite`，也可通过 `ARK_MODEL` 覆盖为套餐支持的 Model Name。不要使用普通地址 `https://ark.cn-beijing.volces.com/api/v3`，否则不会消耗 Coding Plan 套餐额度，而会产生普通方舟调用费用。联网路线会把已确定的产品身份转换成跨境电商英文检索词，再通过 Responses API 的 Web Search 工具补充缺失卖点和场景；检索词只用于搜索，不会覆盖 Amazon Child SKU 确定的商品名。联网仍无卖点时，才从已上传的竞品 HTML 中提取候选卖点供人工确认。

需要直接生图时配置 `GRSAI_API_KEY`。主界面分为三个完整页面，并通过顶部导航切换：第一页保持“资料解析 ↔ 提取参数”左右对应，第二页保持“人工参数 ↔ 当前任务提示词”左右对应，第三页保持“当前提示词 ↔ 参考图与生成结果”左右对应；普通桌面宽度不改成上下布局。资料解析页先选择“单品路线 / 套装路线 / 不同款组合套装”，再选择“本地分析 / 豆包识图 / 联网补充”；Amazon SKU 名称含 `Set`、`Kit`、`Bundle` 或套装字样时，绑定该 SKU 会自动切换到套装路线。“不同款组合套装”必须人工确认，避免把普通同款多件装误判为异款组合；该路线由完整组合参考图直接控制各款身份，提示词只规定完整组合、人物使用、多场景、参数与卖点图中各款如何呈现，不用文字重述产品几何。套装解析后在第二页确认主体、配件、数量及各自的 1688 来源。三页共享当前产品、模板和图组任务，人工参数保存后会重算整套提示词，已生成图片在输入变化后会提示重新生成。来源图先去重，超过 16 张时按原始清单全段均衡抽样，再由豆包按产品身份排除明显无关商品以及证书、检测报告、票据、纯文字表格等证据文档。供应商图只保留当前 SKU 同色及明确相近色候选，相近色须人工选择；竞品图不参加颜色筛选，固定放在最前面。重复图片只显示一次。右侧最多展示 20 张候选图、人工最多选择 6 张，也可拖拽本地 JPG、PNG、WebP 图片并单张删除。用户确认参考图后，可一键把同一组参考图应用到当前模板全部非空提示词，并以最多两个并发任务批量生成整套图片；也可继续单张提交。全部生成后可一键保存 ZIP。下载命名是项目级固定规则：压缩包只使用中文产品名（`产品名.zip`），内部图片只使用中文产品名加连续阿拉伯数字（`产品名1.png`、`产品名2.png`……），不追加日期、图组、图位、用途、历史轮次、连字符或其他标注；生成记录里的下载入口同样遵守此规则。中文产品名按“已提取的中文产品名 → 1688 中文标题或源文件名”依次确定，下载命名不使用内置类目映射；仍无法确定时统一使用 `产品套图`，不得回退为英文名称。VIP 模型额外支持 2048 和 2880 方图。API Key 在 macOS 上可保存到系统钥匙串，启动时读入当前服务进程，不写入页面或项目文件。

从店铺运营系统 S3 打开时，工具 URL 会携带 `store_project_id` 和 `store_sku`。这两个值共同限定当前工作记录；同一浏览器、同一本机的内嵌页与“单独打开”标签页共用该记录，不同子体相互隔离。工具会从运营系统只读接入当前项目最新登记的 Amazon 上品表、以及 S1 已保存且指纹未变化的 1688 HTML，预填到原有资料输入框；不会自动解析或覆盖已保存的解析结果。运营确认资料后，仍需手动点击“解析资料并提取产品信息”。没有已登记的原始文件时，对应输入框保持空白。首次刷新原内嵌页时，仅当旧标签页选中的产品 ID 与 URL 子体相同，或以 `-子体SKU` 结尾，才迁移旧会话资料和生图历史；旧记录不会被删除。直接打开不带这两个参数的独立工具仍保留原先按标签页隔离的模式。此功能不是跨电脑或多人实时同步；同时编辑两个标签页时，后保存者可能覆盖前者，建议一次只在一个标签页编辑。

### API Key 一次配置与自动读取（macOS）

首次运行 `python3 server.py` 时，在终端按提示输入火山方舟和 Grsai Key；输入不会显示，格式通过检查后自动保存到 macOS 钥匙串。后续启动优先使用有效环境变量，其次读取钥匙串；两者均没有可用 Key 时才提示输入。格式检查不代表远端服务已验证密钥有效。

也可以在项目目录运行 `python3 server.py --configure-keys`，单独配置或更新 Key 后退出。更新时直接回车保留原有保存值；已运行的服务需重启才能加载新 Key。环境变量中的 Key 不自动持久化，如需保存请使用此命令。

钥匙串项目服务名为 `prompt-tool.api-keys`，两个账户分别为 `ARK_API_KEY`、`GRSAI_API_KEY`，可在 macOS“钥匙串访问”中管理。如果系统询问访问权限，允许当前 Python 访问这些项目即可。读取或保存失败会显示提示，输入的有效 Key 仍可用于当前进程。其他操作系统继续使用环境变量或每次启动时输入，不保存到磁盘。

可以同时打开多个浏览器标签页处理不同产品。每个标签页分别保存自己的产品资料、参数、提示词、参考图与生图历史；刷新当前标签页会恢复该标签页的进度，不会覆盖其他标签页。浏览器标签标题会显示当前产品名，便于在并行任务之间切换。关闭标签页后，该标签页的工作记录会随浏览器会话结束而清理，因此重要图片仍应及时下载。

1688 资料归属分为“仅当前 Child SKU”“同一 Parent SKU 全部子体共享”和“自动判断”三种作用域。Child 专属资料只写入被绑定的 SKU；Parent 共享资料只写入同父体子 SKU，并继续保留各 Child 的标题、SKU、颜色和专属差异。自动判断只有在商品与款式存在唯一高置信度匹配时才写入，多 SKU 无法唯一确认时停止并要求人工选择。所有供应商事实、卖点证据与参考图都跟随同一作用域，未在作用域内的 SKU 不得从整份 1688 文本回捞尺寸或其他参数。供应商图片匹配失败时暂不显示未经确认的 1688 图片，避免混入其他颜色；竞品图仍保留，第三页可用“重新筛选1688图片”重试。第 1 页左栏放置“商品组合路线”和“信息提取路线”，右栏放置“资料输入”和“资料提取出的产品参数”，不再显示独立的来源摘要模块；采集助手图片只保留链接粘贴区，不提供图片清单文件上传口。

功能：
- 输入 Amazon 类目模板 Excel、1688 HTML 文件、竞品链接 HTML 文件；1688 和竞品 HTML 可多选。
- 可输入 Amazon 类目模板 Excel，用于按子 SKU 提取采购款式；可用行号范围或 SKU 列表限定要提取的款式。
- 点击解析资料，从资料中提取产品名、款式选项、材质、颜色、结构、细节和卖点线索。
- 解析前可选择三条路线：本地分析、豆包识图整理、豆包联网补充。
- 选择解析出的当前产品 / 款式。
- 选择参数规格、功能展示、场景展示、参考链接或植物绑带模型。
- 图片类型由模板决定，一次性输出完整图组提示词。
- 修改左侧可替换参数，例如 Product Name、Material、Color、Structure、Selling Point。
- 商品展开尺寸、材质、工艺和卖点只有在当前商品资料存在证据时才自动填写；包装和物流尺寸不参与商品参数。
- 占位符在页面中以蓝色显示，复制时保留纯文本提示词。
- 每张图可单独复制，也可复制当前产品完整图组。
- 每张提示词卡片可直接调用 Grsai 生成图片，并在任务完成后预览或打开原图。

## 数据口径

- 采购单用于确认已采购的产品款式，不把采购下单数量当作产品参数。
- Amazon 类目模板用于确认变体款式：`Parentage Level = Child` 的行数作为采购款式个数；`Variation Theme Name` 中的字段作为款式属性，例如 `SIZE/COLOR` 读取尺码和颜色。父 SKU 只用于归组，不作为采购款式。指定范围支持 `7-17`、`7,9,11-17` 或直接填写 SKU。
- SKU 和原始款式标签保持不可变，只用于识别与来源追溯；提示词中的 `Option` 不重复颜色，只保留尺寸、数量等非颜色变体事实，纯数字多件装统一写成 `2-Pack` 等明确数量标签。`Color` 始终作为独立参数输出；人工修正颜色后，提示词必须同时剔除 SKU 原始选项中的旧颜色，禁止出现新旧颜色冲突。该规则对当前页面、刷新恢复页面和所有新标签页全局生效。
- 产品自身数量只从款式名、套装描述或 1688 已确认规格中提取，例如三双装提取为 `3 pairs`。
- 不提取、展示或写入提示词 `Product Style` 参数；风格由所选图片模板和具体图位规则控制，避免把供应商或 Amazon 的泛化 Style 字段误当成产品事实。
- 1688 HTML 用于提取产品标题、款式选项、颜色/尺码、材质、规格、尺寸、结构和适配信息。
- 本地分析路线只使用 1688 页面、结构化属性和本地 OCR，不调用豆包。
- 豆包识图路线把筛选后的 1688 参数图、材质图和功能图交给视觉模型，只整理有图片证据的材质、展开尺寸、工艺、结构和卖点。
- 豆包联网路线只用英文商品关键词执行检索，补充仍缺失的卖点和使用场景；关键词不写回商品名，也不通过网络补精确尺寸、重量、数量、具体材质或当前商品独有配置。
- 竞品 HTML 用于参考图组逻辑和筛选卖点，不用于补写未确认参数。
- `Surface Finish / Process` 只记录明确的制造工艺或表面处理，例如哑光、抛光、拉丝、喷粉、电镀、阳极氧化、上釉、印刷、压花、植绒、注塑或压铸；柔软、弹性、厚薄、针织密度、防滑、抗菌防臭、受力均匀和耐用等属性不得混入该字段。来源顺序为人工修改、当前1688精确款式、确认适用于全部款式的1688页面；Amazon、竞品和联网结果均不作为该字段来源。
- 产品本体尺寸使用可增减的 `Product Dimensions` 列表，每行保存“部位名称: 数值 + 单位”，不再限制为固定三个字段。来源顺序为人工修改、当前1688精确款式的使用状态尺寸、确认适用于全部款式的1688尺寸、Amazon Child SKU标题中明确的二维/三维尺寸、已上传竞品页面中的产品参数。Amazon 工作簿 Item/Package Length、Width、Height 及其他尺寸字段一律不采用；包装、物流、外箱、折叠收纳、卷起收纳尺寸也不得进入。
- 尺寸图必须展示列表中的每个尺寸，并把箭头对应到正确轴向或产品部位；可折叠或可展开产品使用完全展开/打开状态。无法确认 `Dimension 1/2/3` 对应轴向时保留通用标签，不绘制误导性箭头。主图、场景图和卖点图只保持正确产品比例，不显示尺寸数字、箭头或标尺。
- 原 `Weight / Quantity` 拆分为 `Product Weight` 与 `Capacity`；数量继续只由 `Product Count / Set` 负责。两项来源顺序均为人工修改、当前1688精确款式明确参数、确认适用于全部款式的1688页面参数、已上传竞品产品参数兜底；任何 Amazon 字段都不作为来源。产品净重排除毛重、包装重量、运输重量和外箱重量，也不根据“轻便”等卖点推测；容量必须有明确数值和容量单位。参数图中重量与容量使用独立文字或小图标信息块，不绘制尺寸箭头，主图、场景图和普通卖点图不显示。
- 产品名优先采用当前 Amazon Child SKU 标题提炼出的基础商品名；1688 只用于核对当前实物身份，不覆盖已确定的 SKU 商品名。
- 资料没有明确参数的产品不借鉴、不参照，只写能提取到的规格。
- 提示词中不展示冗长的 verified data 明细，只保留必要占位符。
- 场景展示模板按 8 张图输出：A 产品主体主场景、B 人物使用主场景、多场景、多角度、产品说明、卖点图 5、卖点图 6、卖点总览。
- 植物绑带模型按 5 张图输出，图片使用阿拉伯数字顺序命名：图一主图场景图、图二白底图、图三多场景使用图、图四卖点图、图五尺寸材质等产品信息详情图。

## 规则分层

- 第 2 页提供醒目的“整套卖点图方案”：每张卖点图可从当前 SKU 的卖点列表人工选择一条，选择随 SKU 和模板保存；调整后旧方案失效并自动重新规划。两张专用卖点图分别采用有依据的场景使用证明和以产品本体为主的细节、材质或经证实的性能证明，两张画面均须清楚展示当前产品；无法用现有事实证明时暂停对应方案，不补造功能。进入第 2 或第 3 页时，如当前 SKU 尚无适用方案，页面会自动使用豆包规划；修改相关参数后会等待输入稳定再重新规划，同一参数版本自动请求最多一次，失败时仍可手动重试。逐项显示主体、产品状态、动作或细节、构图、事实依据及图间区别。规划不要求必须有优质供应商卖点图，但只能使用当前 SKU 的确认事实和卖点，不按产品类目或图号套用固定构图。
- 方案随当前标签页的 SKU 保存。修改产品参数、卖点、证据或模板会使旧方案失效并触发自动重新规划；未规划或缺少依据的卖点图不会提交生图。有效方案写入对应英文提示词，匹配证据图与产品身份参考图一起传给生图接口。自动规划不会自动生成图片。
- 第 2 页的“确认参数，卖点图方案与提示词，进入图组”会同步当前输入、等待当前卖点图规划完成，并逐张核对方案和最新参数已写入对应提示词；未通过时停留在第 2 页显示原因。方案列表以图位和证明方式标明对应卖点图，默认折叠详细依据和修订项；完整提示词先显示摘要，可按图位展开。
- 规划后会额外调用一次豆包复核事实依据与图间区别，并尝试修订展示不清楚的构图；模型复核仍可能漏判，02 页应核对具体内容。“修订或暂停此方案”支持修改动作、构图、依据和英文画面指令；填写暂停原因后，该图将停止提交生图，其他图仍可独立测试。

- 全局规则只控制所有图片都必须遵守的底线：Amazon 1:1、清晰度、英文文字、真实产品、不编造参数、不复制竞品、不出现中文源文字。
- 模板规则只控制图组结构：参数规格模板、功能展示模板、场景展示模板、参考链接模板、植物绑带模型各自决定图片数量、主图/多场景/参数/卖点/总结图的构图任务。
- 场景展示模板的主场景图是全局模板规则：A 以产品本身为主展示并搭配对应场景，B 以人物使用产品状态为主并搭配对应场景；两者都必须有吸引力的真实生活方式场景和空间氛围，产品清楚但不能变成鞋/物品特写；需要通过环境、道具、自然光、前后景和留白建立场景吸引力。
- 所有主图只能使用一个连续、铺满画面的摄影场景，禁止圆形/几何小窗、白色描边、画中画、放大框、拼贴、分屏及带独立背景的第二产品画面。场景主图允许同款产品作为较小的辅助展示再次出现，但必须像真实物体一样直接放在同一场景中的人物服装、装备或环境表面上，并与主场景共享光线、透视、景深、接触阴影和色调；不得形成独立小图。
- 场景展示模板的多场景图是全局模板规则：必须输出 4 个完整真实使用场景，使用四宫格/四 panel 构图，每个 panel 都要有环境、道具、空间/户外上下文和自然使用动作；不能退化成产品特写、单品摆拍、细节图或选项图。
- 场景展示模板的产品说明图是全局模板规则：必须有清晰主标题，例如 `Product Information` / `Product Details`；只展示 2-3 个已验证信息点，文字要有专业层级、对齐、留白、细分割线/小图标和高级感，不能变成长文、密集表格或无质感的普通标注。
- 场景展示模板和功能展示模板的卖点图默认每张展示 1 个卖点；只有两个卖点在 1688 中指向同一证据画面、能够由一个统一展示场景自然表达时才合并到同一张图。连续卖点图不能重复卖点；图中文字只使用保留原意的 2-4 个英文词短标签，不添加额外口号、长句、重复 claim 或密集文案。
- 表面工艺作为所有图片的产品外观约束，但不自动成为卖点或场景文案；仅在材质微距图、产品细节图或产品信息图中确有展示价值时，才允许使用简短英文标签，主图和场景图不得显示工艺名称。
- 场景展示模板第 7 张卖点总览图的左下角白色圆形产品区必须严格遵守当前 SKU 数量：普通单品只展示 1 个完整产品；已确认的多 Pack SKU 展示与 Pack 数一致的完整独立产品，不得少放、多放、融合或为了构图额外复制。
- 植物绑带模型复用已有模板中对应图类的生图规则和限制：图一参考主场景图规则，根据产品实际要求决定是否出现人物模特；图二参考白底主图规则，只展示当前产品本体；图三参考多场景使用图规则；图四参考卖点图规则；图五复用其余模板中已有产品详情图 / 产品信息详情图的生图规则和限制，重点呈现尺寸、材质、结构、规格等已验证产品信息。
- 项目不使用内置类目映射、关键词类目识别或专用品类规则。产品身份、参数、结构、场景和卖点只来自当前 Amazon SKU、明确绑定的 1688 资料、图片证据及有来源的联网结果。
- `Category / 类目` 不作为产品字段，不读取 Amazon Browse Path，也不进入任何图片提示词。卖点图只能依据当前 SKU 身份、已确认卖点和产品证据设计展示方式，不得根据模型推断的类目补充结构、场景、道具、功能或声明。
- Use Scene 支持通过本地服务代理联网补全：资料提取后若少于 3 个场景，会结合当前产品身份和卖点，先生成跨境英文产品关键词，再依据公开网络证据填写 3-5 个去重的英文场景；也可在左侧手动触发或编辑。联网按钮只采用本次有证据的搜索结果，不混入旧场景。没有联网确认到场景时显示“没有参考场景信息”，不使用类目、通用或模型推测的兜底场景。
- 产品跑偏只通过当前 SKU 身份、已确认参数、参考图和通用真实性约束控制，不追加任何按类目命中的结构锁、场景、道具、卖点或文案。
- `Multiple optional colors` 默认不作为卖点，不进入卖点字段、卖点图或生成提示词。
- 下载时仅选择 1 张图片会直接保存为图片文件；选择多张图片或整套图组时才生成 ZIP 压缩包。
- 新产品适配必须改善通用证据提取或人工确认流程，不新增基于产品名称关键词触发的专用品类分支。
